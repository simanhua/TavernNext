# Commit Player Operations as Save history

Scene Workspace gameplay controls submit commands through `scene.action`; after the Scene server accepts the command, TavernNext atomically commits its Player Operation summary as an immutable system-history message and anchors it to the corresponding Scene State transition, including an empty transition when the action has no state patch. The server may return an `operation` containing the actual costs and outcome, which takes precedence over the optional frontend-authored summary; the frontend summary remains a compatibility fallback when the server omits one. A server-authored operation requires explicit acceptance and must pass the same Player Operation validation before any state or history is committed, so a random outcome need not be known by the frontend before settlement.

This lets the next user-triggered Agent Run observe the action in chronological history without starting an automatic run, while current Scene State remains authoritative for outcomes. `result` remains transient data returned to the workspace; durable outcomes belong in Scene State and their factual summary belongs in the Player Operation. Direct SDK patches stay semantically silent, and Compatibility Runtime controls and historical Scene Views remain outside this write path.
